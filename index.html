Why AgentFlow

Make agent work
visible and durable.让 Agent 的工作
可见、可验、可继续。

The agent still does the actual work. AgentFlow supplies the durable structure around it: files you can inspect, state you can resume, and branching rules that do not depend on an LLM “feeling right.”

真正执行任务的仍然是 Agent。AgentFlow 提供的是它外面的确定性结构：可以检查的文件、可以恢复的状态，以及不靠模型“感觉”来判断的分支规则。

MD

Markdown is the source of truthMarkdown 就是真源

A master WORKFLOW.md plus one STEP.md workspace per step. Read it, edit it, diff it, commit it. flow.json stays derived metadata.

一个主 WORKFLOW.md，每一步一个 STEP.md 工作区。可读、可改、可 diff、可提交；flow.json 只是派生元数据。

Execution runtime

The agent works.
The runtime keeps score.Agent 负责干活，
Runtime 负责不走偏。

AgentFlow does not become another agent. It compiles the latest workflow, exposes only READY nodes, resolves conditions and merges, records results, skips inactive paths, and keeps the next batch explicit.

AgentFlow 不会变成另一个 Agent。它编译最新工作流，只返回 READY 节点，自动处理 Condition / Merge，记录结果、跳过无效路径，并明确给出下一批任务。

agentflow — runtime
$ af next release-flow --json
{ flowRevision: 12,
ready: ["run-tests"],
skipped: [], gates: {...} }

$ # agent reads 02-run-tests/STEP.md
$ af done release-flow run-tests \
--result '{"ok":false,"failures":2}' \
--revision 12
✓ result saved · condition resolved false
✓ activated: fix-failures · skipped: publish

$ af next release-flow
READY fix-failures

$ af status release-flow

Install

The easiest install
is to ask your agent.最省事的安装方式：
直接交给你的 Agent。

Give the repository URL to a coding agent that can run shell commands. It can clone AgentFlow, run the platform installer, sync the skill directories and verify everything with af doctor.

把仓库地址发给任何能执行 shell 的编码 Agent。它可以自己 clone、运行对应系统的安装器、同步 skills，并用 af doctor 完成验证。

✓No plugin marketplace or harness-specific package required.不需要插件市场，也不需要为每个 Agent 单独打包。
✓Existing flows under ~/.agent-flow/flows survive reinstall/update.重新安装 / 更新不会删除 ~/.agent-flow/flows 中的现有流程。
✓Default Studio address: 127.0.0.1:4317.Studio 默认地址：127.0.0.1:4317。
